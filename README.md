# بوت متجر الشحن (game4station)

بوت تيليجرام بلغة Python يبيع منتجات game4station بمحفظة لكل عميل.
يشتغل على Render، وبياناته في Firestore مشفّرة.

## المزايا

- كتالوج مقسّم حسب القسم، والسعر يُحسب من سعر المزود مع نسبة ربح تقدر تغيّرها من البوت.
- محفظة لكل عميل. الحسابات كلها بـ `Decimal`، وما فيه `float` أبداً.
- الخصم والطلب يصيرون في Transaction وحدة، ومربوطين بـ `order_uuid`. لو ضغط العميل الزر مرتين ما ينخصم منه مرتين.
- إذا انرفض الطلب، أو رد المزود بخطأ، يرجع المبلغ للعميل تلقائياً.
- إذا انقطع الاتصال وما عرفنا هل الطلب تم أو لا، **ما يرجع المبلغ**. البوت يعيد إرسال الطلب بنفس `order_uuid`، والمزود يرجّع الطلب الأصلي لو كان موجود، فما يتكرر.
- مهمة في الخلفية تتابع الطلبات المعلّقة (`wait`) كل دقيقة، وتبلّغ العميل أول ما يكتمل طلبه.
- تنبيه لك لما يقل رصيدك عند المزود، أو لما يرد المزود بخطأ إعدادات (مثل 123 لما يكون الـ IP مو مسموح).
- حد لعدد الطلبات من كل مستخدم (ضد السبام)، ووضع صيانة، وحظر وفك حظر.
- أدوات المالك تتحقق من الآيدي في كل أمر، والآيديات تنحفظ في متغيرات البيئة بس.

## الأمان والتشفير

| البيانات | طريقة التخزين |
|---|---|
| آيدي تيليجرام | اسم المستند بصمة HMAC، والآيدي الأصلي مشفّر داخل المستند (البوت يحتاجه عشان يراسل العميل) |
| الرصيد، المبالغ، آيدي اللاعب، ردود المزود، السجلات | مشفّرة بـ AES-256-GCM |
| حالة الطلب، اسم المنتج، الكمية، التواريخ | بدون تشفير، عشان البحث والترتيب |

- كل قيمة مشفّرة مربوطة بالمستند والحقل حقها. لو أحد نسخ رصيد عميل وحطه في مستند عميل ثاني من قاعدة البيانات، فك التشفير يفشل.
- المفاتيح لها رقم إصدار عشان تقدر تبدّلها: `ENCRYPTION_KEYS=v2:<جديد>,v1:<قديم>`. المفتاح الأول يشفّر، والكل يقدر يفك.
- **احفظ نسخة من `ENCRYPTION_KEYS` و`HMAC_KEY` خارج Render** (في مدير كلمات مرور مثلاً). إذا ضاعت، ما تقدر تقرأ أي رصيد.

## التشغيل خطوة بخطوة

### ١. توليد المفاتيح

```bash
python -m bot.keygen
```

### ٢. Firebase / Firestore

1. أنشئ مشروع في Firebase، وفعّل Firestore بوضع **Native**.
2. من Project settings ثم Service accounts، ولّد مفتاح JSON. حط محتواه في `FIREBASE_CREDENTIALS_JSON`، كنص أو مشفّر Base64.
3. ارفع قواعد الأمان (ترفض كل شي من خارج السيرفر)، والفهارس، وسياسة TTL للسجلات:

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

سياسة TTL تحذف السجلات من مجموعة `logs` تلقائياً بعد `LOG_RETENTION_DAYS` يوم (الافتراضي 180).

4. نسخ احتياطي يومي يحتفظ بآخر 14 يوم:

```bash
gcloud firestore backups schedules create --database='(default)' --recurrence=daily --retention=14d
```

### ٣. Render

1. اربط الريبو. ملف `render.yaml` يجهّز الخدمة لحاله.
2. استخدم خطة **Starter** المدفوعة. المجانية تنام، فيتأخر الرد على العملاء، وتتوقف متابعة الطلبات المعلّقة.
3. عبّي متغيرات البيئة من `.env.example`. ما تحتاج تحط رابط الـ Webhook لأن Render يعطيه للبوت تلقائياً (`RENDER_EXTERNAL_URL`).

### ٤. الـ IP عند game4station (الخطأ 123)

عناوين Render الخارجية مشتركة مع عملاء ثانيين، وممكن تتغير. إذا game4station يقيّد الـ IP، عندك خيارين:

- تضيف عناوين Render الخارجية الخاصة بمنطقتك عندهم. تلقاها في Dashboard تحت Connect ثم Outbound.
- أو تستخدم Proxy بعنوان ثابت (مثل QuotaGuard أو Fixie) وتحط رابطه في `G4S_PROXY_URL`. البروكسي يُستخدم لطلبات game4station بس.

## أوامر المالك

| الأمر | الوظيفة |
|---|---|
| `/admin` أو زر «🛠 لوحة المالك» | اللوحة: رصيد المزود، الطلبات المعلّقة، الصيانة، السجل |
| `/credit ID المبلغ [ملاحظة]` | شحن رصيد عميل (العميل يوصله إشعار) |
| `/debit ID المبلغ [ملاحظة]` | خصم من رصيد عميل |
| `/user ID` | الرصيد وآخر الطلبات |
| `/ban ID` / `/unban ID` | حظر وفك حظر |
| `/margin 10` | تغيير نسبة الربح |
| `/maintenance on\|off` | إيقاف البيع وتشغيله |
| `/order UUID` | تفاصيل طلب، فيها التكلفة ورقم المزود |
| `/refund UUID` | استرجاع يدوي لطلب معلّق، بعد ما تتأكد من لوحة المزود |
| `/recheck` | تحقق فوري من الطلبات المعلّقة |
| `/logs` | سجل عمليات المالك |

العميل يشحن رصيده يدوياً في البداية: يحوّل لك المبلغ، وأنت تشحن له بأمر `/credit`.

## مراحل الطلب

```
تأكيد ─► خصم + إنشاء الطلب (Transaction وحدة)
       ─► newOrder بنفس order_uuid
            accept ─► مكتمل
            wait   ─► المتابعة تتحقق بالـ uuid كل دقيقة
            reject أو خطأ من الـ API ─► استرجاع تلقائي
            انقطاع أو مهلة ─► "unknown": بدون استرجاع، وإعادة إرسال بنفس الـ uuid
```

## نقاط لازم نتأكد منها مع game4station

1. **أسماء الحقول:** التوثيق يذكر `playerId` بس. البوت يرسل أول حقل باسم `playerId`، والحقول اللي بعده باسم عنوانها. إذا عندهم منتج يطلب أكثر من حقل، اسألهم عن الأسماء الصحيحة.
2. **صيغة `check`:** التوثيق يكتب `orders=[ID1,ID2]`. البوت يرسلها بالأقواس، والتحقق يكون لطلب واحد في كل مرة.
3. **سعر المزود:** يتحدّث قبل الخصم مباشرة. إذا تغيّر بعد ما شاف العميل السعر، يطلع له السعر الجديد ويعيد التأكيد.

## التطوير المحلي

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```

بدون `WEBHOOK_BASE_URL` البوت يشتغل بوضع Polling، وهذا مناسب للتجربة على جهازك.

```bash
python -m bot.main
```

الاختبارات تستخدم تخزين في الذاكرة بدل Firestore، ونسخة وهمية من game4station وتيليجرام. يعني ما تحتاج أي مفاتيح عشان تشغلها.
